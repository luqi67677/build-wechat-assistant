# 模型检测、推荐与任务路由

本文件是必读参考。顺序固定为：先读取非秘密配置 → 在任何远程或可能计费的模型调用之前分类凭据来源 → 对共享或未知来源取得用户决定 → 再验证能否使用 → 最后才决定是否推荐新模型。不要让用户重复配置已经真实验证可用的能力。

本文件中的命令形状都是 Agent 内部实现，不是让用户照抄的教程。每次执行前按操作模式绑定 direct / `isolation_guard.py run` / `run-cloud`；所有路径、Profile 与根用途先机器核验。普通步骤由 Agent 直接执行；必须用户本人在场的模型秘密或 OAuth 由 Agent 调用 `scripts/launch_trusted_handoff.py` 主动打开受信窗口。只有宿主无法代开时才解释原因并提供一条已完成替换的原子命令，不能把 `<...>` 或多步命令交给小白。

## 1. 静默检测已有配置

先用当前 Hermes Profile 运行针对性读取，不读取或打印 `.env`，也不要读取包含 `api_key` 字段的整段辅助配置：

```bash
hermes -p <Profile> config get model.default
hermes -p <Profile> config get model.provider
hermes -p <Profile> config get auxiliary.vision.model
hermes -p <Profile> config get auxiliary.vision.provider
hermes -p <Profile> config get delegation.model
hermes -p <Profile> config get delegation.provider
hermes -p <Profile> fallback list
```

某个键不存在时只记为“未配置”，不要把技术错误原样发给用户。不得直接运行并捕获 `hermes -p <Profile> auth list`：当前 v0.40.0 会输出 provider、凭据标签、认证类型和来源，虽然不显示 token，仍可能把用户自定义标签或账号线索写进 Agent 日志。来源分类只能使用本轮认证动作的受控记录、目标 Profile / 隔离根边界，以及当前版本能提供的布尔状态；无法无秘密证明时标记 `未知`。

先完成下方“凭据来源必须可解释”的分类和用户决定，才可运行 `hermes -p <Profile> doctor` 或最短真实请求。`doctor` 也可能访问 provider，不能当作免费、离线的配置读取。只向用户总结结论，不展示密钥、被遮罩的密钥或整份诊断输出。

区分三个状态：

- **已配置**：配置中存在模型或凭据，但尚未调用。
- **连接可用**：已用一次最短、无工具的中文请求真实返回。
- **能力已验证**：视觉模型还必须用一张真实图片验证；仅凭模型名称不能算识图通过。

本地模型还要检查运行服务和模型文件是否存在。配置指向本机端口但服务未启动时，标为“已配置但当前不可用”。

## 2. 先向用户展示检测结果

检测完成后先给结论。若主模型未配置，继续读取 `china-models.md` 并实时核验候选，不能停下来只问用户。检测区使用简短格式：

```markdown
检测到以下模型：

- 日常主模型：<名称>｜<连接可用/已配置但未验证/当前不可用>｜识图：<支持/不支持/未核实>｜官方介绍与价格：<核验后的官方 HTTPS 链接>
- 识图模型：<名称或未配置>｜<验证状态>｜官方介绍与价格：<核验后的官方 HTTPS 链接>
- 复杂任务模型：<名称或未配置>｜<验证状态>｜官方介绍与价格：<核验后的官方 HTTPS 链接>

推荐：<复用现有方案或只补充缺失能力>。
```

不要展示 base URL、provider 内部配置、模型别名、密钥状态明细或一长串候选 ID。

## 3. 官方地址是强制项

模型目录、能力和价格会变化。对每个检测到并准备复用的模型，以及每个新推荐模型：

1. 用浏览或搜索工具核对模型厂商当前官方页面。
2. 优先链接模型详情或价格页；需要用户创建密钥时，再附官方控制台或密钥页。
3. 地址必须来自模型厂商官方域名或 Hermes 官方文档，不使用搜索结果页、聚合站、博客、推广落地页或第三方教程。
4. 官方页面未明确视觉、工具调用或价格时，标记“官方未确认”，不自行推断。
5. 链接失效或当前无法访问时，不推荐该模型，或明确标记“官网地址未验证”。

推荐卡片至少包含：模型名称、日常聊天、识图、工具调用、费用级别、选择理由、验证状态、官方地址。价格只使用当前官方值并注明计费单位与核验日期，不承诺长期不变。

## 4. 什么时候询问用户

### 已有模型满足需求

直接推荐复用，不再问预算或让用户重选。只在真实测试可能产生明显费用时先说明。

### 已有模型缺少能力

只问缺失项。例如主模型可用但不能识图，只问：“现有模型不能看图片，我建议增加一个识图模型，需要吗？”

### 没有可用模型

先打开当前 Hermes 官方 Quickstart，核对目标地区和当前环境是否能使用官方 OAuth（网页登录授权）路径；可以使用时将它作为最短候选，因为用户不必手工搬运 API key。OAuth token 仍是会落盘、可撤销的秘密，不能宣传为“没有凭据”或“不会泄露”。

官方 OAuth 不可用、用户不选择或不满足数据/费用要求时，才按 `china-models.md` 核验 DeepSeek、Kimi、GLM、千问当前 API 可用候选；硬件满足时单列本地模型。官方页面无法访问或 Hermes 不兼容的候选明确排除。展示可交付方案和一个明确推荐，再每次只问一个：

1. “你更重视省钱、简单，还是效果？不确定的话我推荐省钱又够用。”
2. “你会不会把图片发给助手看？不确定的话我建议支持识图。”

用户说已有某家模型时，先确认他拥有的是可供 API 调用的账号或 API key，再用隐藏输入配置；不要要求把 API key 发到聊天里。最终推荐只保留一个首选，不把未核验候选凑数。

## 5. 对话优先的安全登录与 API key 录入

“安全输入”指 Agent 只把秘密交给官方认证或凭据存储，不让它进入对话、普通文档、命令参数、脚本内容或日志。隐藏输入框只能防止屏幕回显，不能证明操作系统剪贴板历史、跨设备剪贴板或密码管理器日志中从未保存过该值；不得作这种承诺。不要为了录入 API key 让小白额外安装终端。

按以下优先级自动选择当前已存在的通道：

1. Agent 或宿主应用提供的原生 secret/password 输入控件。
2. Hermes Dashboard 或桌面应用中经过实际检测、能够管理 API key 的掩码输入框，或模型厂商官方 OAuth 登录。
3. 系统密码管理器能够直接填充到上述掩码控件。
4. 已安装终端中的真实 TTY 隐藏输入，例如 `hermes -p <Profile> auth add <provider>`；不让用户把 API key 拼进命令。

上述 Dashboard/桌面应用优先级只适用于普通新建或已明确授权的增量目标，而且必须先在界面中确认当前选中的确切 Profile，不得点击“设为活动 Profile”去改变其他助手。**受保护验收不得使用机器级 Hermes Dashboard** 或桌面应用录入秘密：它们可以管理同机多个 Profile，当前没有证据证明 UI 会被隔离 runner 的 `HOME`、`HERMES_HOME` 与 shared auth 根约束。受保护验收只允许隔离 runner 内不会把 stdout 回传给 Agent 的受信 TTY，或在该隔离根内发起的模型厂商官方 OAuth；无法满足就停止在真实认证前。

国内模型厂商（DeepSeek、Kimi、GLM、千问）通常不提供 Hermes 的 OAuth 登录；只有当前官方资料或 Hermes 实际确认支持时才把厂商 OAuth 列入候选，未核验不得作为首选。

禁止使用 Word、TextEdit、记事本、备忘录、邮件草稿、普通文本文件或聊天框暂存 API key。这些工具可能自动保存、同步云端、进入最近文件或保留版本历史。也不要把 API key 拼进 `--api-key`、Shell 命令、脚本正文、执行日志或 URL；只允许 Hermes 官方向导、凭据池或受权限保护的秘密存储保存它。

优先使用 OAuth 或密码管理器直接填充。用户选择复制粘贴前，先说明系统剪贴板历史或云同步可能保留内容；输入完成后可由用户通过系统界面清理当前剪贴板，但这不能证明所有历史副本已删除。

若以上通道都不存在，普通新建/已授权增量目标告诉用户：“当前没有可确认安全的 API key 输入框。为了避免它留在聊天或文档里，我先停在这里；确认目标 Profile 后打开 Hermes Dashboard、桌面应用，或启用当前工具的秘密输入可以继续。”受保护验收只提示打开绑定隔离 runner 的受信 TTY 或官方 OAuth，不推荐机器级 Dashboard。不得降低安全标准继续配置。

OAuth 登录 URL、device code（设备码）、回调参数和二维码与 API key 一样属于短时凭据。开始前先用当前 `hermes -p <Profile> auth add --help` 和官方资料确认 provider 及认证类型；OAuth 固定走 `auth add <provider> --type oauth`，API key 固定走 `auth add <provider> --type api_key` 的隐藏输入。未明确 provider 时禁止运行通用 `model` 向导：当前版本可能自动进入 Nous Portal 等未选择厂商，不能让用户在交互中猜。

Agent 按操作模式构造 direct / `run` / `run-cloud` 命令，并调用 `launch_trusted_handoff.py`。API key 固定使用同步原生隐藏框：本地普通或受保护模式先为 Hermes 建立三路均为真实 TTY 的本地伪终端，云端模式先建立远端交互 TTY；只有观察到 Hermes 的 `Paste your API key:` 掩码提示后才显示隐藏框，再把秘密送入 stdin。命令同时预填 `--label <Profile>`，不让用户进入第二个标签提示。禁止先从弹窗取 Key 再把它管道到尚未进入掩码状态的本地进程；也禁止先从弹窗取 Key 再把它管道到尚未进入掩码状态的 SSH，这两种情况都会触发终端回显。交接器吞掉原始子进程输出，只返回 `SAVED` 或不含路径和秘密的错误码；检测到秘密回显、提示缺失、输出超限、保存回执缺失或弹窗取消时立即失败关闭。OAuth 与二维码仍由脚本主动打开独立受信终端，用户不输入终端命令，只在窗口完成官方登录、扫码或手机确认。runner 继续机械检查 stdin/stdout/stderr，非 TTY 返回 `trusted_tty_required`。Agent 不能代开时先解释当前宿主为何缺少安全窗口控制；用户明确继续后才提供一条无占位符、无秘密的原子命令。不得要求 `cd`、`source`、SSH、多次复制粘贴或第二次空回车，也不得让用户发送 URL、设备码、回调地址或整段输出。两种安全通道都没有时停止。

macOS 固定使用系统原生密码框（AppleScript `display dialog` 的 `hidden answer`），输入栏必须真实可见、可聚焦、可编辑，并在录入真实秘密前完成一次只含假值的可视验收；禁止使用 Tkinter `simpledialog`，因为部分系统 Python/Tk 组合会只显示按钮而不显示输入栏。Windows/Linux 才允许使用各自经实际验证的原生或 Tk 图形输入实现；任何平台看不到可编辑输入栏时都必须取消并修复，不能让用户反复试错。

截至 2026-08-10，[Qwen Code 官方认证页](https://qwenlm.github.io/qwen-code-docs/en/users/configuration/auth/)已标明 Qwen OAuth 免费层停止，并说明新版本移除了 `qwen auth` 命令；全新安装不得推荐或尝试这条登录路线。当前 Hermes v0.40.0 的模型向导仍可能打印旧提示 `qwen auth qwen-oauth`，这只能视为过期兼容提示。只有未来 Qwen 官方重新确认服务可用、目标 Qwen CLI 的 `auth --help` 也实际保留该动作时，才允许解析绝对路径并通过 `isolation_guard.py run-qwen-auth --mode help`/`login` 执行；runner 仍必须绑定当前模式 HOME、清除继承秘密，且 `login` 机械拒绝非 TTY。任一条件不满足就选择其他当前可用 provider，不能退回裸命令。

### 凭据来源必须可解释

认证成功只记录来源类别，不记录凭据值：

- `当前 Profile 专用`
- `全局共享`
- `进程环境`
- `共享 OAuth`
- `未知`

命名 Profile 不能证明凭据专用。在任何远程或可能计费的模型调用之前完成分类。共享或未知来源必须先向用户说明账单、限额与撤销会影响哪些助手并取得同意；严格隔离测试只接受测试隔离边界内的凭据。独立 Hermes 根中建立的 OAuth 可以使用，但仍如实标记为该隔离根内的共享 OAuth；生产根的全局/共享认证、外部进程环境和未知来源禁止借用。真实中文回复只能证明“调用成功”，不能证明“凭据隔离”。

来源分类以当前 Hermes 能安全提供的认证状态、目标 Profile、全局认证存储、共享 OAuth 存储和启动进程环境的“是否存在”证据为准，只记录 provider 和来源类别，不记录值、掩码值、文件内容或完整路径。当前 CLI 不能可靠区分时直接标记 `未知`，不要从“请求成功”反推来源。不得直接运行并捕获 `hermes -p <Profile> auth list`，也不得捕获顶层 `status --deep`；后者会汇总认证、路径、环境和平台元数据，不能因为没有显示完整 token 就当作可公开日志。

在任何认证、`doctor` 或真实请求之前，先应用并通过 `apply_chat_safety_baseline.py`，确认 CLI 与 Weixin 同时精确只启用 `clarify`。认证后、第一次真实中文请求前再次运行 `check_pre_qr_safety.py`；向导导致工具、MCP、推理或记忆边界漂移时，重新应用基线再检查。只有第二次 PASS 才运行明确“不调用任何工具”的最短中文请求。模型探测成功后再运行一次 `apply_chat_safety_baseline.py`：它只收紧已批准 Profile 内模型运行时新建的 `cache`、`auth.json` 与 Weixin 状态目录，不触碰其他 Profile 或宿主认证目录；随后再运行 `check_pre_qr_safety.py`。两项 PASS 前不得进入微信扫码。

## 6. 三个可实现的模型角色

### 主模型：必选

负责日常对话、工具调用和最终回复。优先考虑中文自然、工具调用稳定、价格符合预算；追求极简时可选择同时支持视觉的主模型，但必须真实验证 Hermes 的图片路径。

### 辅助视觉模型：按需

主模型不支持图片或视觉费用过高时，配置 `auxiliary.vision`。图片会由 Hermes 的视觉路径调用该模型，用户无需手动切换。只读取该节点的 provider、model 和必要的非秘密连接信息，不输出 `api_key`。

### 强模型或专业 Agent：可选

复杂推理可以配置 `delegation.provider` 与 `delegation.model`，让主助手按规则调用 `delegate_task`。代码开发优先使用 Codex、Claude Code 或 OpenCode Skill。首次使用更贵的委派模型前说明费用，高频委派先约定预算。

## 7. 诚实说明自动路由

Hermes 能自动路由特定辅助任务，例如视觉、网页提取、压缩和标题生成；fallback 是故障备用，不是任务选择器。可交付的规则是：

- 普通聊天 → 日常主模型。
- 图片 → 辅助视觉模型。
- 明显复杂的多步任务 → 主助手判断后委派强模型。
- 开发任务 → 用户选定的专业编程 Agent。
- 主模型失败 → fallback 链。

不要声称“配置多个主模型后，Hermes 会自动为每条普通聊天选择最便宜或最强模型”。

## 8. 验证与完成条件

至少测试：

1. 主模型完成一次最短中文对话。
2. 配置视觉模型后，用一张无隐私图片完成识别；无法证明路由时标记未验证。
3. 配置强模型后，用一个无副作用问题验证委派；未配置则跳过。
4. 模型不可用时，用中文说明“发生了什么 + 用户该怎么办”。

只有主模型真实返回、所需视觉能力真实通过，才显示：`✓ 第 3 步已完成`。

## 9. 已运行助手更换模型

不承诺绝对零中断。当前 Hermes 对已经配置的 provider（模型提供商）支持在会话内用 `/model` 切换且通常不需重启 gateway，但新凭据、网络、模型工具能力、现有长会话和平台状态仍可能导致短暂失败。用户要求严格零中断时，若当前官方实现和真实故障注入不能证明，就停止承诺并说明限制。

受控顺序：

1. 记录旧 provider、模型 ID、fallback 链和当前会话，但不记录密钥值；写明恢复旧路由的方法。
2. 添加新 provider 或凭据时不覆盖旧默认。通过 Hermes 官方隐藏输入完成认证。
3. 用隔离本地会话对新模型做最短中文请求；需要搜索、识图或其他工具时分别测试。失败就保留旧路由并停止。
4. 新模型通过后，在主人当前 Weixin 会话中使用 `/model <已配置的新模型> --session` 做会话级切换；参数必须以当前 `/model` 帮助为准。发送一个真实但无副作用的微信任务，检查回复、工具和费用边界。
5. 成功后才由用户决定是否用 `--global` 持久化为默认。模型切换会重置 prompt cache（提示缓存），长会话下一条可能增加输入费用；必要时创建新会话。
6. 微信测试失败时，通过不依赖模型推理的 `/model <旧模型> --session` 恢复旧路由并重新验证；如果平台命令也不可用，再按当前服务范围受控重启。不能同时改模型、工具、人格和 gateway 版本。

fallback 只能降低因单一模型故障失联的概率。至少做一次可恢复的故障注入：临时让主模型返回可控失败，确认切到已验证 fallback；测试后恢复原配置。没有真实故障证据时只写“已配置”，不能写“自动切换已验证”。
