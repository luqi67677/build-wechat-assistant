## 1. 用户真正要做什么

Hermes 当前通过官方 Weixin 集成连接腾讯 iLink Bot API。扫码后得到的是独立的 iLink 机器人身份，不是把扫码者的普通个人微信号变成脚本账号；这条路线不使用注入、Hook 或协议逆向，但不能承诺绝对零风险。

正常流程中，用户只做两件事：

1. 在 Agent 自动打开的临时窗口中查看二维码；
2. 用微信扫码，并在手机官方页面确认。

用户不输入终端或 SSH 命令，不选择平台，不选择私聊权限，不选择群聊权限，不填写 user ID，也不选择 `Done`、启动或开机自启。二维码和短时登录 URL 是临时登录凭据，不进入聊天、Agent 工具输出或日志，也不通过普通截图分享。

这里仍需要一个临时系统窗口，是因为 Hermes v0.30.0 的扫码函数要求真实 TTY 才能安全渲染二维码；TTY 只是二维码显示载体，不是要求用户学习终端。没有能隔离显示二维码的可信窗口时必须停止，不能用 Word、TextEdit、记事本或普通网页文本框代替。

## 2. Agent 自动完成什么

打开二维码前，Agent 按当前模式完成模型探测后的权限重新收紧、运行 `check_pre_qr_safety.py` 并记录非秘密状态基线。已有 `WEIXIN_*` 标记只代表上一次配置，不能当成本轮进展；没有认证过期证据时阻止重复扫码。只有本轮启动后的新鲜状态变化和扫码后安全检查都通过，才能登记完成。

Agent 通过 `scripts/launch_trusted_handoff.py --kind weixin-setup` 调用 `scripts/setup_weixin_direct.py`，直接进入 Weixin 二维码登录函数。普通全新模式绑定当前 Profile；受保护验收绑定 `isolation_guard.py` 创建的本轮 `local-test` 根，真实账号或跨轮验收绑定 `local-persistent` 根；云端使用 `run-cloud` 等价的清洁环境，绑定 `cloud-service` 根与最终服务账号 HOME。三种模式都必须精确绑定目标 Profile 和 Hermes 启动器。

交接器只回报窗口是否成功打开，不会把 stdout 回传。普通 Agent PTY 会捕获二维码或短时 URL，因此不能作为扫码显示窗口。

直达助手自动写入以下固定策略，用户无需看英文菜单：

- 私聊策略为 allowlist，只保留本次扫码主人；
- 两级 allow-all 都关闭；
- 群聊关闭，群聊名单为空；
- home channel 与扫码主人相同；
- API 与 CDN 使用已核验的官方地址；
- 不安装、不启动、不重启 gateway，也不设置开机自启。

通用向导里的 `Allow all direct messages` 表示任何人都能私聊使用，风险过高；直达助手永远不会选择它。以前需要用户选择 `Only allow listed user IDs`、`Disable group chats` 和 home channel 的工作，现在由固定安全策略完成。

助手输出只保留二维码和非秘密中文状态；隐藏短时 URL、token 和 account ID。它结束后 Agent 运行 `scripts/check_profile_safety.py`，核对许可名单恰好一个主人、home channel 与主人相同、群聊关闭、端点无覆盖、敏感文件权限合格、gateway 仍停止。

## 3. 各系统如何显示二维码

### macOS

Agent 使用系统自带 Terminal 自动打开一次性二维码窗口。用户不输入命令，只扫码；完成后可以关闭该窗口。

### Windows

Windows 用户不需要安装 Windows Terminal、Git Bash 或任何第三方终端。Agent 使用操作系统自带的新控制台窗口运行已绑定的直达助手；必须保留该窗口的标准输入、标准输出和标准错误，不能重定向到空设备，否则二维码不可见。用户只扫码，不使用方向键、回车或命令行。

若运行宿主无法创建系统控制台，直达助手返回 `trusted_tty_required`；Agent 先说明“当前环境无法安全弹出二维码窗口，微信尚未连接”，然后停止。只有用户明确选择末级回退，才提供一条已经填好且不含秘密的原子命令；仍无真实 TTY 就不扫码。

### Linux 桌面

Agent 选择已存在的系统终端模拟器并打开一次性二维码窗口。没有桌面终端时，按“无法安全显示二维码”停止，不要求用户临时安装图形终端。

### 云服务器

服务器通常没有桌面。Agent 在用户电脑上自动打开绑定 `ssh -tt`、远端服务账号、隔离根、Profile 与直达助手的临时窗口。root SSH 只走已核验的 `root-runuser`，非 root 管理员走 `sudo`，只有 SSH 用户明确等于服务账号时才允许 `direct`。用户不输入 SSH 或服务器命令。

当前实现输出的短时 URL 未验证可以在同一部手机直接完成授权；只有一部手机且没有第二块可信屏幕时停止，不让用户先付费或猜测操作。

## 4. 异常与恢复

### 出现全平台菜单

如果窗口出现 `Select a platform to configure:`、`Done`、Discord、WeCom 或 WhatsApp 等列表，说明误入了 Hermes 通用 `gateway setup`，不是本 Skill 的 V0.3 直达路线。即使列表里没有 Weixin，也不是用户操作错误。

用户不要滚动、不要按方向键、不要选 `Done`。Agent 只终止当前精确 Profile 的这一个交互进程，重新执行直达助手；不得扩大到其他 Hermes 进程、其他 Profile 或已经配好的既有生产助手。

### 二维码不完整或乱码

Agent 关闭本轮未完成的临时窗口，确认没有写入完整 Weixin 状态且 gateway 仍停止，再用更大的系统窗口重新启动同一条直达流程。二维码或 URL 不复制进聊天。

### 扫码后没有完成

等待手机官方页面确认和远端轮询。窗口退出但状态不完整时，保持 gateway 停止并报告“微信扫码未完成，请回到对话重新开始”。未知状态不能当作未创建；用户需先在微信官方界面确认授权结果。

### Agent 无法观察同一 Profile

主动状态陪同是默认方式；报屏协议只作备用。Agent 无法访问同一 Profile 或无法安全区分新旧状态时，用户最多只说“二维码已出现”“手机已确认”或窗口上的非秘密中文错误，不能发送二维码截图、URL、账号 ID、token 或整段终端输出。

### 看到旧版权限或启动页面

`How should direct messages be authorized?`、`Allowed Weixin user IDs`、`How should group chats be handled?`、`Start the gateway now?` 或开机自启提示都表示走错了通用向导。用户不要继续选择；Agent 停止这个精确交互进程并检查是否发生了未授权写入或服务启动。第 5 步才启动 gateway。

## 5. 完成条件

“微信连接成功”只表示上游登录函数返回，不表示第 4 步完成。必须同时满足：

- 本轮出现新鲜的 Weixin 状态变化；
- 直达助手完整退出并报告安全策略已保存；
- 扫码后安全检查全部通过；
- 私聊许可名单恰好一个主人，home channel 与主人相同；
- allow-all 与群聊均关闭；
- gateway 保持未启动，服务状态与扫码前基线一致；
- token、二维码、短时 URL 和账号 ID 没有进入聊天、日志或普通截图。

完成后 Agent 告诉用户：“微信连接和安全权限已经自动保存；请回到对话等待下一步，先不要发微信消息。”

第 4 步只完成连接配置。第 5 步写入并核验人格后才允许启动 gateway、发送真实微信消息和设置开机恢复。

持久服务的恢复语义仍按平台区分：macOS 和 Windows 只能在目标用户登录后恢复，不代表停留在系统登录界面也在线，并且电脑仍需开机且未休眠；云服务器才按已核验的 systemd 开机恢复流程验收。
