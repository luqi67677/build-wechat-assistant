# 微信助手验收与完成状态

本文件只在第 5 步人格写入、gateway 准备临时启动后读取。模拟、静态检查和命令返回不能代替真实微信结果。

本文件中的启动、停止、服务安装、状态检查与验收命令全部由 Agent 执行；用户只在微信里发送验收消息，或在真实重启前确认中断窗口。

## 1. 三层完成状态

- **聊天可用**：基础门槛、当前同一 Profile gateway 和交接后的真实微信往返通过。
- **持久运行已验证**：聊天可用后启用精确服务，受控重启 gateway，再次真实微信往返通过。
- **开机恢复已验证**：持久运行通过后真实重启电脑或服务器，确认系统确实进入新一次启动，再次真实微信往返通过。

第 11 项稳定性和安全故障注入属于发布级质量验收，可中途暂停。模拟状态不能满足持久运行或开机恢复结论，不承诺固定耗时。

## 2. 真实验收清单

1. 本地问“你是谁？”，收到简体中文回复。产品名、命令、配置键和 URL 可以保留原文，其他叙述不应出现无意义英文填充词或未翻译错误。
2. 在微信私聊同一问题，收到回复；再发一条真实任务，确认不是固定欢迎语。
3. 若配置识图，发一张图片并确认视觉模型实际工作。
4. **搜索实测（仅用户需要时）**：先确认 `web` 工具已在 Weixin 明确启用且模型支持工具调用，再发真实查询。成功才列入已验证；未选择时标记“未配置”，不影响基础助手完成。
5. **记忆实测（仅用户需要时）**：启用对应开关与工具后，必须用三个新会话验收。会话 A 写入带唯一标签的无敏感事实；会话 B 确认读取后移除；会话 C 确认持久记忆块已不存在。任一步失败或无法清理都不得列为已验证。从持久记忆移除 ≠ 从聊天历史、日志或模型提供商记录中抹除；需要删除这些记录时另走对应平台流程。告知用户不要让助手记密码、银行卡号——它是助手，不是保险柜。
6. **任务规划实测**：发一个无副作用的规划请求，检查约束、步骤和优先级；只生成计划，不执行外部动作。
7. **实时信息实测（仅已选择时）**：只有已启用并验证安全时间来源才查询时间；天气、新闻同理。云端还要核对服务器时区。
8. **扫码后执行边界实测**：必须在新的 Weixin 会话中测试提示注入、禁用工具不可调用、审批拒绝和越界拒绝。仅聊天档确认 `skill_manage` 不可用；明确启用 `skills` 时确认 `skills.write_approval=true` 且每次写入先审批。
9. **访问控制证据**：许可名单非空且只有主人，群聊关闭。有第二个测试账号时再验证未授权用户不会直接使用；没有测试账号时将外部负向测试列为未验证，不能伪造通过，也不否定已通过的配置证据。
10. **稳定性实测**：连续进行 10 轮不同中文对话，发送一条接近日常长度上限的长消息，再快速连续发送两条短消息；不得乱码、无故截断、丢失、重复回复或退回固定欢迎语。
11. **恢复实测**：受控重启当前 gateway 后再次发送真实任务。受保护本地验收不得用 Ctrl+C 作为完成证据；Agent 在另一受控进程中使用同一隔离 runner 执行精确的 `-p <Profile> gateway stop`，状态确认已停后再重新 `gateway run`。该前台重启通过仍只能登记“聊天可用”，没有安装并核对受管服务就不是“持久运行已验证”。只有隔离环境中能安全故障注入时才测试网络短断、模型 401、429 或余额不足；未执行时标记未验证，不改坏生产凭据来凑测试。错误说明必须包含“发生了什么 + 用户该怎么办”。

自我介绍必须使用用户设定的名字和职责，不能自称默认的 “Hermes Agent”。回答“你是谁”时只用一到两句自然中文；不得提模型名、测试日期、“系统提示”“能力清单”“规则”“已验证/未验证”，也不得主动罗列现在不能做的功能。发现未验证能力被说成可用时，人格验收失败，更新能力清单并创建新会话复测。

## 3. 可选能力的独立验收

基础微信助手通过后，每项增强能力单独登记，不用基础聊天成功替它背书，也不让可选项失败破坏基础助手。发布门禁会在全新隔离 Profile 中执行 `mcp add` 与 `mcp test`，证明知识库、飞书和编程三个 stdio 服务能保存、重连并发现精确工具清单；这仍只是工具层。每项至少保留三层证据：受限工具本身、模型在新会话中的实际调用、微信中的真实结果；缺哪层就明确写哪层未验证。

### 知识库

1. 只读模式完成目录/固定文档内的一次列出、搜索和指定内容读取；外部专用诱饵、另一链接或 `../` 必须在访问前拒绝。
2. 私有内容要发送给模型前，单独说明模型提供商、发送范围和用途并取得同意；不同意时只保留工具层证据。
3. 用户选择写入后，用无私人内容的测试笔记完成一次创建和一次带旧版 SHA-256 的更新；同名、版本冲突、符号链接和超大内容各至少验证一个错误路径。
4. 回滚本轮测试变更，再证明文件有后续修改时自动回滚会拒绝。执行器没有通用删除工具。
5. 飞书读取需核对真实 document ID；飞书创建需锁定固定父目录。隔离 Gateway 中还要用显式传入的 Node.js 真实绝对路径完成模型层调用，不能用普通终端的 `PATH` 成功代替。真实权限不足和未授权目录都要给出“发生了什么 + 下一步怎么做”。
6. 最后从微信提出一次读取请求；若用户确实需要写入，再从微信确认一项可恢复的测试创建。工具层、模型层、微信层、只读和可写状态分别记录。Hermes 0.30.0 的交互命令行在 `prompt_toolkit` 已占用输入且没有审批回调时会让 MCP elicitation（逐次确认）失败关闭；这不是微信层证据，也不能通过关闭确认来绕过。用 MCP 客户端单独验证执行器，再以 gateway 的真实微信确认和回执作为最终证据。

### 编程智能体

当前包的可交付执行器仅为 Codex；Claude Code 与 OpenCode 只有比较和检测流程，没有等价受限适配器时不得登记“微信编程已接入”。

1. 只检测用户选中的工具和一个 Git 仓库根；已有未提交修改时必须停止。
2. 用无私人内容的演示仓库调用真实所选编程 Agent；`prepare` 完成后证明原项目没变，并展示变更文件、摘要和补丁 SHA-256。
3. 第二次确认后才把补丁应用到原项目，运行一个与修改相关的测试；确认没有 commit、push、publish 或 deploy。
4. 回滚本轮补丁；再制造一个后续修改，证明自动回滚会拒绝覆盖。
5. 最后从微信完成一条同样受限的小任务并收到中文回执。假 Codex 只能证明执行器编排，不能登记真实 Codex 或微信编程通过。

### 日常自动化

1. 核对任务所在环境、时区、唯一投递目标、数据源、费用和失败行为；本地与云端不得为同一内容重复建任务。
2. 创建后以正向业务回执和 `cron list` 为准，不能只看退出码；越界脚本必须被拒绝且不能出现在任务清单。
3. 先执行 `cron run <job_id>`，再以 `cron runs` 的 completed 回执和包含本轮新鲜标记的输出文件证明真实运行。模型或数据源任务还要核对本日日期和来源新鲜度。
4. 微信真实收到正确消息后才登记投递通过；本地 delivery 或运行回执不能代替微信送达。
5. 实际走完 pause、resume；remove 属于外部状态移除，用户确认后才执行，并核对任务不再出现在 `cron list --all`。

## 4. 从临时运行切到持久服务

聊天可用通过后，先停止当前临时 gateway，并用同一 Profile 的深度状态证明已停。普通本地路线调用 Hermes 的 Profile 定向 `gateway stop`；受保护本地路线必须通过 `isolation_guard.py run ... -- -p <Profile> gateway stop`，不得向整个终端进程组发送 Ctrl+C 后就假定清理完成。云端还必须证明同一全新服务账号没有第二个 gateway。严格本地验收若现有助手受保护，不安装持久服务，前台重启成功后仍只能登记“聊天可用”。

```bash
# 普通本地路线；受保护验收不执行
hermes -p <Profile> gateway install --force --start-now --start-on-login

# 全新云端服务账号路线
python3 <Skill绝对路径>/scripts/isolation_guard.py run-service --root <本轮专用Hermes根> --hermes <HERMES绝对路径> -- -p <Profile> gateway install --force --no-start-now --start-on-login
python3 <Skill绝对路径>/scripts/systemd_env_guard.py check-prestart --profile <Profile> --hermes <HERMES绝对路径> --expected-hermes-root <本轮专用Hermes根> --expect-enabled enabled
python3 <Skill绝对路径>/scripts/isolation_guard.py run-service --root <本轮专用Hermes根> --hermes <HERMES绝对路径> -- -p <Profile> gateway start
python3 <Skill绝对路径>/scripts/systemd_env_guard.py check-runtime --profile <Profile> --hermes <HERMES绝对路径> --expected-hermes-root <本轮专用Hermes根> --expect-enabled enabled
```

服务定义、启动器、Profile、Hermes 根、有效环境、active/enabled 状态和单实例轮询都必须现场核验。服务启动、受控重启和真实重启后分别再做一次真实微信往返。macOS launchd、Windows 服务和本地 Linux 若没有当前版本的等价自动检查器，无法取得现场绑定证据时只保留“聊天可用”，把另外两层标记未验证。

## 5. 最终完成条件

只有 `flow-contract.json` 中七项基础门槛全部通过，且当前同一 Profile gateway 正在运行、交接后真实微信往返再次通过，才可说：“这位助手当前聊天可用，真实微信收发、人格、有效访问控制和执行边界均已通过。”

搜索、持久记忆、识图、知识库、编程和定时推送分别标记已验证、未配置或未验证。按当前模型官方单价和本次实际用量说明计费；没有用量证据时不给固定月费。
