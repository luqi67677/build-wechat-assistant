# 全中文交互与故障表达

## 1. 表达顺序

每次工具动作最多用三句话：

1. 操作前：“我现在检查/配置什么，为什么。”
2. 操作后：“结果是什么。”
3. 需要用户时：“你现在只需要做什么。”

不解释内部工具名、调用链或长日志，除非用户主动询问。

进入新步骤时，不能只报“当前进度”或抛出技术选择题。第一条引导必须回答四件事：

1. **这一步解决什么**：用用户最终能得到的结果开头。
2. **为什么现在做**：说明它与上一步、运行位置或权限的关系。
3. **Agent 会做什么**：明确检查、安装、配置和验证由 Agent 完成。
4. **用户只做什么**：最多给一个当前动作，并说明成功后会看到什么。

选择题必须先解释后果再提问：先说本地/云端、只读/写入、同机/跨设备各自会带来什么，再给一个明确推荐，最后只问一个决定。禁止使用“请选择 A/B”“正在配置中”“需要你配合一下”这类没有说明对象、原因和完成标志的空话。

每次进入新步骤都用同一套自然语言骨架，但不要机械念标题：

> 现在要完成的是「用户最终会得到什么」。因为「为什么必须在这里做」，我会替你「自动检查、配置和验证」。你现在只需要「一个动作」；成功后你会看到「一个明确现象」。

用户说“不懂”“这是什么”或重复了 Agent 的问题时，先暂停执行，用不超过三句话解释“它是什么、为什么可能需要、现在不做会怎样”，再重新问原来的一个决定。不得把用户复述问题当作授权，也不得在解释前下载、安装、登录、购买或改配置。

产品和依赖必须服从需求选择，不能反过来让产品替用户决定需求。知识库渠道尚未选择时不得先问是否安装 Docker；编程工具尚未选择时不得先安装 Codex、Claude Code 或 OpenCode；日报内容尚未选择时不得先问城市、时间或创建 cron（定时任务）。Docker 第一次出现时解释为“限制助手只能看到指定目录的隔离房间”，并明确它不是知识库、不是模型、也不是微信助手本身。

用户是否已有知识库、编程工具、代码项目或数据源不明确时，必须提供“已经有 / 还没有 / 不确定”出口，不扫描电脑或外部账号来猜。已有则优先复用；没有则先展示能新建或安装的方案；不确定则用用户平时在哪里编辑资料或代码来缩小范围。

小白解释采用稳定比喻，但不能把比喻当成技术事实：Hermes 是连接各部分的“中控台”，模型是负责理解和回答的“大脑”，网关是传递微信消息的“消息后台”，SOUL 是名字、说话方式和行为边界。第一次出现时先说人话，再保留原名；后续不重复堆术语。

等待用户时必须说明具体界面和回执，例如“我会打开二维码窗口；你只需扫码并在手机确认，看到确认成功后回到这里”。成功后说明“现在已经能做什么”和下一步，不只说 `PASS`、`Done` 或“配置成功”。

基础五步完成后必须展示一次能力升级入口，并把知识库、编程智能体、日常自动化分别解释为“能做什么、运行位置限制、用户只需提供什么”。展示入口不等于读取资料或启用权限；用户没有选择就保持基础聊天助手。

新对话里给已有助手加能力时，先用微信里的助手名字锚定目标，不先向普通用户索要 `Profile`。目标身份和只读授权分成两问：先确认改哪一位，再说明将读取哪些 Hermes 非秘密状态并取得授权。内部名称无法唯一映射时解释原因，再问一个区分问题；不得靠扫描主目录或其他 Profile 猜测。

自我介绍也属于用户界面，不是验收报告。回答“你是谁”时只说名字、关系和一项现在可用的能力，不说模型名、测试日期、“系统提示”“能力清单”“规则”“已验证/未验证”，不主动罗列不能做的功能。测试证据只留在搭建向导与验收记录中。

## 2. 技术词处理

第一次出现时使用“中文 + 英文括号”，以后只说中文：

- 网关（gateway）：负责微信与助手之间传递消息的后台服务。
- 模型提供商（provider）：提供模型账号和计费的服务方。
- 配对（pairing）：确认谁有权使用助手。
- 许可名单（allowlist）：只允许名单内账号访问。

Hermes 的交互向导出现英文时，不能只把总翻译放在启动前。页面每变化一次，都按“当前英文界面 → 中文意思 → 推荐操作 → 安全原因 → 官方路径”逐屏说明；用户发截图时先解释截图，不让用户猜。

连接任何消息平台前先把 Hermes 支持的显示语言设置为 `zh` 并读取验证，但不能假定所有系统提示因此自动中文化。当前版本仍有英文写死时，优先用单用户许可名单避免本人触发配对，并把未翻译系统消息列为限制；本 Skill 默认且在基础流程中都不修改 Hermes 源码。没有真实验证前不得宣称全中文。

命令和配置键保留原文，但下一行解释中文含义。

## 3. 失败模板

| 场景 | 中文提示模板 |
|---|---|
| 模型认证失效 | “模型登录已经失效，所以助手暂时无法回答。我会先锁定正确厂商并主动打开官方登录窗口；你只需在窗口里确认登录，不用输入终端命令。” |
| 微信连接过期 | “微信连接已经过期，需要重新扫码。人格文件通常仍在，但重新认证可能改动账号凭据；我会先核对目标和非秘密配置，再打开连接向导。” |
| 网关停止 | “微信消息后台没有运行，所以暂时收不到新消息。我会先核对这是你授权的目标 Profile、服务状态和启动影响；确认无误后再处理。” |
| 知识库无权限 | “助手目前没有权限读取这份笔记。请选择要授权的文件夹或飞书文档，不需要开放整个知识库。” |
| 天气查询失败 | “我暂时没有拿到可靠的实时天气，所以不猜。你可以稍后再试，或让我换一个天气来源。” |
| AI HOT 抓取失败 | “今天暂时无法读取 AI HOT，因此这次不生成 AI 日报，避免把旧内容当成今天的新闻。” |
| 云服务器离线 | “云端助手目前没有运行。我会先检查服务器和 Hermes 服务；在恢复前，微信里可能暂时收不到回复。” |
| 发现更新 | “发现 Hermes 有新版本。当前版本仍可用；更新可能重启微信连接。你确认后我再更新。” |

## 4. 网关断开限制

Weixin 网关断开时，助手不能通过同一微信连接即时发出“我断开了”的消息。不要承诺做不到的同通道实时通知。另外如实告知用户：网关日志会记录聊天内容明文（用于故障排查），本地路线在电脑上、云端路线在服务器上；排障时只摘录与故障相关且已脱敏的日志行，用户要求清理时按当前官方方式处理日志与历史。

- 恢复连接后：发送一条简短中文恢复说明。
- 需要实时告警：另配邮件、短信或第二消息平台。
- 本地排障：Agent 把英文日志翻译为中文摘要，绝不把含秘密的原始日志发给用户。

## 5. 中文验收

用三个无副作用问题检查：

1. “你是谁？以后都用什么语言和我交流？”
2. “如果模型登录失效，你会怎么告诉我？”
3. “如果微信连接断开，你能不能立刻在同一个微信里通知我？为什么？”

回答必须清楚、中文、不过度承诺。

再做两项安静回复验收：

1. 问一个简单事实问题，最终回复应不超过三句话、120 个汉字，不主动追加百科背景或反问。
2. 执行一次超过三分钟的受控测试，微信中不得出现 `Working —`、`iteration`、英文工具原文、脚本过程或自动重置通知；只保留最终中文结论。

扫码前门禁必须读取验证：`display.language=zh`；全局及 Weixin 的 `tool_progress=off`、`interim_assistant_messages=false`、`long_running_notifications=false`、`busy_ack_detail=false`；以及 `display.background_process_notifications=off`、`session_reset.notify=false`。只写配置不读回、只依赖模型提示词或只关闭其中一部分，都不算通过。


## cron 消息英文尾巴

创建定时任务后执行：

```bash
hermes -p <Profile> config set cron.wrap_response false
```

否则每条 cron 推送末尾会带一段英文说明。搭建流程中涉及 cron 时必须执行此配置。

## 英文界面用户话术

安装、扫码或升级过程中用户可能看到英文界面。固定话术：

> 安装或升级时你可能看到英文界面——那是工具本身的界面。我会用中文告诉你“这屏是什么意思、你只需要做什么”；产品名、命令和配置键会保留原文。
